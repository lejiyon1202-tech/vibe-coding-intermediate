CLAUDE.md 
# HR 업무 보조 — 나의 Claude 설정

## 역할
당신은 HR 전문가 보조 AI입니다.
인사·교육·채용 관련 문서를 작성합니다.

## 절대 규칙
- 개인정보(이름, 사번, 연봉)는 절대 출력 금지
- 결론 먼저, 배경 나중 (두괄식 항상)
- 한국어로만 답변

## 선호 형식
- 교육 기획안: Kirkpatrick 4단계 구조
- 보고서: 요약 → 상세 → 액션 아이템
- 코드: 주석을 한국어로

## 금지 표현
- "~인 것 같습니다" (단정하지 않는 표현)
- "죄송합니다"로 시작하는 문장
필수 4섹션
역할(Role) — 어떤 전문가로 행동할지
절대 규칙(Rules) — 반드시 지킬 것
선호 형식(Format) — 출력 양식
금지 표현(Banned) — 쓰면 안 되는 것
실무 팁
• 처음엔 3~5줄로 시작 — 길수록 좋은 게 아님
• 3회 이상 같은 수정 요청 → CLAUDE.md에 규칙 추가
• 팀 공용: git에 커밋 → 팀원 전원 동일 설정
⚠️
주의
파일 경로·API 키·개인 토큰은 절대 CLAUDE.md에 쓰지 마세요. 팀 공용 파일이면 git에 올라갑니다.

SKILL.md를 저장하면 Claude 재시작 없이 즉시 반영. 실시간으로 수정하며 테스트 가능.
🔗
$ARGUMENTS 변수
/기획서 팀빌딩 신입사원 60분 처럼 명령어 뒤 인자를 자동으로 주입합니다.

• 특정 프레임워크(STAR, SBI, OKR)를 반복 적용할 때
• 팀 전체가 동일한 방식으로 Claude를 써야 할 때
실사용 예시
/기획서 [회의 핵심 3줄]

Hooks 설정 — 위험 명령 자동 차단 예시

.claude/settings.json 
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "cmd=$(jq -r '.tool_input.command'); if echo \"$cmd\" | grep -q 'rm -rf'; then echo '위험 명령어 차단됨'; exit 2; fi"
      }]
    }],
    "PostToolUse": [{
      "matcher": "Write",
      "hooks": [{
        "type": "command",
        "command": "echo \"[LOG] 파일 수정: $(date)\" >> ~/claude-log.txt"
      }]
    }]
  }
}
위 설정이 하는 일
🛡️ rm -rf 명령 감지 시 즉시 차단
📝 파일 수정 시마다 자동 로그 기록

matcher: "Bash" → bash 명령만 검사
matcher: "Write" → 파일 쓰기만 검사
matcher: "*" → 모든 도구 검사
matcher: "mcp__github__*" → GitHub MCP 전체 (v2.1.118+)
활용 아이디어
• Stop hook: 작업 완료 시 슬랙 알림 전송
• PreToolUse: prod DB 접근 전 확인 요청
• PostToolUse: git push 후 CI 상태 확인
• SubagentStop: 에이전트 결과 자동 저장
• mcp_tool (v2.1.118+): MCP 도구에 직접 Hook 적용
✨
mcp_tool 신패턴 (v2.1.118+)
기존: type: "command" → 셸 스크립트 경유
신규: type: "mcp_tool", server: "...", tool: "..." → MCP 직접 호출. 중간 스크립트 없이 더 안정적.
⚠️
주의
Hook 스크립트는 Claude와 같은 권한으로 실행됩니다. 신뢰할 수 없는 코드를 Hook에 넣지 마세요.

Subagents — 여러 Claude가 동시에 일합니다

🤖
한 줄 정의
복잡한 작업을 여러 전문 에이전트에게 분배해서 병렬로 처리하는 기능. 내가 지시하면 각 에이전트가 독립적으로 작업하고 결과를 취합합니다.

• 리서치 + 초안 작성을 동시에 해야 할 때
• 여러 파일을 독립적으로 분석할 때
• 회의록 정리 + 성과 보고서를 병렬로 만들 때
주의 사항
❌ Subagent 안에서 다시 Subagent 생성 불가 (중첩 금지)
❌ Subagent끼리 직접 통신 불가
✅ 메인 Claude가 결과를 취합

Subagents 자가진단 — 병렬 처리로 시간을 아끼세요

지금 당장 병렬화 가능한 업무
  • 리서치 + 보고서 초안 동시 작업
  • 여러 파일의 독립적 번역·요약
  • 회의록 정리 + 다음 아젠다 준비
  • 여러 채널 고객 문의 동시 답변 초안
  • 여러 팀원 주간 보고 취합·요약
Subagents vs 단일 Claude 비교
단일 Claude: A완료 → B완료 → C완료 (직렬)
Subagents: A+B+C 동시 (병렬)

3개 작업 각 10분 → 단일: 30분 vs Subagents: ~12분

복잡할수록 효과 극대화
💡
실습 과제
내 업무 중 "A가 끝나야 B를 할 수 있는" 구조가 아닌 것들을 찾아보세요. 그게 바로 Subagents 대상입니다.

MCP 연결 방법 — CLI 명령어 하나로 시작

터미널 — MCP 서버 추가 
# GitHub MCP 추가 (project scope)
claude mcp add @modelcontextprotocol/server-github \
  --scope project \
  -e GITHUB_TOKEN=$GITHUB_TOKEN

# 설치된 MCP 목록 확인
claude mcp list

# MCP 제거
claude mcp remove github
.claude/settings.json — 수동 설정 
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {"GITHUB_TOKEN": "$GITHUB_TOKEN"}
    }
  }
}

자주 묻는 질문 — 기본편 Q1~Q8

Q1
CLAUDE.md를 얼마나 자세히 써야 하나요?
처음에는 3~5줄로 시작하세요. AI가 엉뚱한 결과를 냈을 때마다 이유를 추가하는 방식으로 보완하는 것이 훨씬 낫습니다.
Q2
Skills, CLAUDE.md, Hooks 중 뭐부터 시작해야 할까요?
CLAUDE.md → Skills → Hooks 순서 권장. CLAUDE.md가 있어야 나머지도 일관되게 작동합니다.
Q3
Hooks가 잘못 설정되면 Claude Code가 아예 안 되나요?
exit 1(경고)은 계속 진행. exit 2(강제 차단)는 특정 도구만 막습니다. settings.json에서 hooks 섹션 삭제 시 즉시 원상 복구됩니다.
Q4
여러 프로젝트에서 같은 Skills를 쓰고 싶어요
User 계층(~/.claude/skills/)에 저장하면 모든 프로젝트에서 사용 가능합니다.
Q5
MCP 서버 연결 후 팀과 공유하려면?
settings.json에서 실제 토큰 대신 "$GITHUB_TOKEN"처럼 환경변수 이름만 남기고 공유. 팀원이 각자 로컬에서 환경변수를 설정합니다.
Q6
Subagents를 쓰면 시간이 더 걸리지 않나요?
짧은 작업은 맞습니다. 복잡·다단계 작업은 병렬 실행으로 오히려 빠릅니다. 30초 이내 작업은 Claude에게 직접 요청이 낫습니다.
Q7
CLAUDE.md에 민감한 정보를 넣어도 되나요?
절대 안 됩니다. 평문 파일이라 git에 올라가거나 다른 사람이 볼 수 있습니다. 민감 정보는 .env 환경변수로 관리하세요.
Q8
Skills 파일명은 어떻게 정해야 하나요?
name 필드 값이 /명령어가 됩니다. 파일명을 name과 동일하게 유지하고 영문 소문자+하이픈 형식을 권장합니다.

Q9
Hooks에서 쓸 수 있는 환경변수는?
$CLAUDE_TOOL_NAME · $CLAUDE_TOOL_INPUT · $CLAUDE_TOOL_RESULT · $CLAUDE_TOOL_INPUT_FILE_PATH. 상세 목록: code.claude.com/docs/en/hooks
Q10
회사 보안 정책에 위반될 수 있나요?
MCP는 외부 서비스 연결이므로 보안팀에 확인하세요. CLAUDE.md·Skills는 로컬 파일이라 비교적 안전하지만 민감 정보를 넣지 않는 원칙을 지키세요.
Q11
CLAUDE.md가 점점 길어지는데 언제 정리해야 할까요?
① 스크롤 없이 전체가 안 보일 때 ② 새 규칙이 기존 규칙과 충돌할 때. 핵심 10줄 + @파일명 참조 구조로 분리하는 것이 가장 관리하기 쉽습니다.
Q12
Skills 명령어 이름이 겹치면?
더 구체적인 계층(Project > User)이 우선 적용됩니다. 팀 공유 Skills는 /팀명-명령어 접두어 권장. /memory 같은 내장 명령어 이름은 피하세요.
Q13
Hooks에서 Slack 등 외부 알림을 보낼 수 있나요?
http 타입으로 외부 URL에 POST 요청을 보낼 수 있습니다. 응답이 느린 API는 PostToolUse 또는 Stop 이벤트에서만 사용 권장.
Q14
커스텀 Subagent를 팀원과 공유하려면?
.claude/agents/ 폴더를 git에 커밋하면 됩니다. Subagent 파일에 API 토큰 등 민감 정보를 직접 넣지 않도록 주의하세요.
Q15
MCP 서버가 갑자기 응답하지 않으면?
claude mcp list로 서버 상태 확인 → 문제 시 claude mcp remove [이름] 후 재추가. 사용하지 않는 서버는 월 1회 정기 정리하세요.

실무자가 자주 틀리는 패턴 8가지

❌ 1. CLAUDE.md 과다 작성
300줄 이상이면 성능 저하. 핵심 규칙 10개 이내 + @참조파일 구조로 분리.
❌ 2. Hooks exit 2 너무 광범위하게
모든 Bash를 차단하면 Claude Code가 아무것도 못 함. grep -q 'rm -rf'처럼 위험 명령어만 골라 차단.
❌ 3. API 토큰 settings.json 직접 입력
git에 올라가면 토큰 즉시 노출. "$GITHUB_TOKEN"처럼 환경변수 참조만 사용.
❌ 4. 간단한 작업에 Subagents 남용
독립 컨텍스트 시작 비용 존재. 30초 이내 작업은 Claude에게 직접. 대규모·다단계에만 사용.
❌ 5. 처음부터 모든 설정 한꺼번에
동시에 여러 설정이 잘못되면 어디가 문제인지 찾기 어려움. CLAUDE.md → Skills → Hooks 순서로 하나씩.
❌ 6. Skills를 너무 많이 만들기
쓰지 않는 Skills는 관리 부담. 월 3회 이상 쓰는 작업만 등록. 10개 이하로 유지하면 명령어를 외울 수 있습니다.
❌ 7. Subagent 하나에 역할 과부하
"만능 에이전트" 설정 시 각 작업 품질 저하. Subagent 하나에 역할 하나. 복잡한 작업은 여러 Subagent로 분리.
❌ 8. 안 쓰는 MCP 서버 방치
시작 속도 저하 + 보안 노출 증가. claude mcp list로 월 1회 점검 → 안 쓰는 서버 제거.
